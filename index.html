学习目标

这个项目帮助你建立和 Codex 协作的基本能力：明确目标、提供上下文、拆分任务、验证结果，并逐步沉淀自己的提示词库。

你负责

  • 明确目标和业务背景
  • 判断方案是否符合真实需求
  • 完成最终验收

Codex 负责

  • 阅读和解释代码
  • 定位问题和相关文件
  • 执行修改并运行验证

Course

六个核心章节

01 认识 Codex

Codex 是一个可以和你一起工作的代码协作者。它可以阅读项目、修改文件、运行验证、解释错误，并帮助你把复杂任务拆成可执行步骤。

适合做什么

  • 解释项目结构和启动方式
  • 查找功能入口和调用链
  • 修复 bug、实现小功能、补充测试
  • 审查代码风险，整理文档和脚本

第一条原则

先让 Codex 了解上下文，再让它执行任务。上下文越清楚，结果越可靠。

02 读代码

读代码是使用 Codex 的基础能力。一个好的开始方式，是让 Codex 先建立项目地图，再进入具体功能。

练习任务

  • 解释目录结构和项目启动方式
  • 找到页面、接口或功能入口
  • 追踪函数调用关系
  • 总结模块职责和数据流

03 改代码

让 Codex 改代码时，最重要的是把任务缩小。小任务更容易验证，也更容易发现问题。

推荐流程

  1. 描述目标和背景
  2. 让 Codex 先阅读相关代码
  3. 确认修改计划
  4. 执行修改并运行验证
  5. 总结改动和剩余风险

04 调试与测试

调试时，Codex 最有用的地方是帮助你缩小问题范围：错误发生在哪里、为什么发生、怎样验证修复有效。

提供信息

  • 报错信息和复现步骤
  • 期望结果与实际结果
  • 相关文件或功能描述
  • 最近改动过什么

05 代码审查

让 Codex 做代码审查时，要明确它应该优先看风险，而不是只总结改了什么。

审查重点

  • 明显 bug、边界情况和行为回归
  • 安全、权限和性能风险
  • 是否缺少必要测试
  • 命名和结构是否容易维护

06 自动化工作流

熟悉 Codex 后，可以让它帮你把重复任务变成稳定流程，比如整理文档、统计数据、生成测试数据或发布说明。

推荐顺序

  1. 先手动完成一次
  2. 让 Codex 总结步骤
  3. 找出重复和容易出错的环节
  4. 再考虑脚本、文档或自动化

Prompts

常用提示词

读项目

请先阅读这个项目的结构，告诉我主要模块和启动方式。先不要修改文件。

改代码

我想实现 X 功能。请先给出修改计划，指出会改哪些文件，等我确认后再动手。

调试

这是报错信息和复现步骤。请先分析最可能的原因，并定位相关代码。先不要修改。

代码审查

请像资深工程师一样 review 当前改动，重点关注 bug、边界情况、行为回归和测试缺口。

Practice

第1周练习

第1天

认识项目结构

让 Codex 阅读项目结构，说明主要目录、启动方式和核心文件。

第2天

定位功能入口

选择一个具体功能，让 Codex 找到代码入口并解释调用链。

第3天

做一个小修改

先让 Codex 给计划，再执行一个很小、容易验收的修改。

第4天

调试一个问题

提供报错或复现步骤，让 Codex 定位并修复问题。

第5天

补测试

判断是否需要测试，并覆盖关键边界情况。

第6天

代码审查

让 Codex review 当前改动，按风险严重程度排序。

第7天

复盘沉淀

总结最有用的提示词，更新自己的提示词库。
